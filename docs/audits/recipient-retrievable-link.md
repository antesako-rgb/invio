# Retrievable personalized RSVP link

Generated contract matches `get_invitation_recipient_link_token({ p_recipient_id: string }): string`; generated types were not edited. No database or public RSVP changes.

The server-only repository calls that RPC only and validates its 64-character text result without assuming a token encoding. The server action strictly validates the recipient UUID, rejects additional authorization fields and returns ActionResult with token or a stable existing error code. RPC authorization remains authoritative. NOT_FOUND covers missing recipient/legacy credentials; FORBIDDEN covers denied access; RECIPIENT_ACTION_FAILED covers unexpected failures. No raw errors are returned or logged.

Details mounts a feature-specific link section only for the open recipient. It fetches the credential separately and uses window origin plus the existing locale-aware getPathname helper for `/invitation/rsvp/[token]`. Copy uses clipboard after a user click; Open uses a new tab with noopener/noreferrer. Loading, unavailable, forbidden and retryable failure states are localized. Closing/editing/switching Details unmounts the section and releases its state; late responses are ignored. Create still consumes its own RPC token without another credential lookup and clears its success state on close. Product copy no longer claims the link cannot be retrieved later.

Security review: the list projection and application recipient model remain credential-free. There is no direct private-table access, token_hash query, browser storage, cookie write, token logging or analytics/error metadata. The action receives only recipient ID; project/invitation membership is checked by the DB RPC. No service-role bypass is introduced. Public token-based get_public_rsvp/submit_rsvp were not changed.

TypeScript passed. Targeted tests cover RPC arguments/result, malformed/missing credentials, error mapping, strict action input, localized URL construction, existing Details loading/copy/open/error states, ignored responses after unmount, unchanged create behavior and list isolation. Live database authorization and visual browser behavior were not exercised by these mocked tests. Exact SQL error variants should be checked against the deployed RPC if they differ from the existing project error conventions.
